**LVM** insère une couche entre les disques et les systèmes de fichiers : on agrandit un volume à chaud, on ajoute un disque à un groupe, on déplace des données d'un disque à l'autre sans arrêt, on prend des instantanés. Il est utilisé par défaut par les installations RHEL et souvent Debian/Ubuntu serveur.

```text
Disques / partitions  →  PV (pvcreate)  →  VG (vgcreate)  →  LV (lvcreate)  →  système de fichiers
```

## Créer et étendre

```bash
sudo pvcreate /dev/sdb /dev/sdc
sudo vgcreate vg_data /dev/sdb /dev/sdc
sudo lvcreate -n lv_donnees -L 500G vg_data
sudo mkfs.xfs /dev/vg_data/lv_donnees
sudo lvextend -r -L +200G /dev/vg_data/lv_donnees          # -r agrandit aussi le système de fichiers
sudo lvextend -r -l +100%FREE /dev/vg_data/lv_donnees
sudo vgextend vg_data /dev/sdd                              # ajouter un disque au groupe
pvs ; vgs ; lvs -a -o +devices
```

Agrandir un disque de VM : augmenter le disque dans l'hyperviseur, puis `sudo pvresize /dev/sdb` (ou `growpart /dev/sda 3 && pvresize /dev/sda3` pour une partition) avant `lvextend`.

Réduire : possible avec ext4 (démonté, `lvreduce -r -L 300G …`), **impossible avec XFS**.

## Déplacer et retirer un disque

```bash
sudo pvmove /dev/sdb                 # déplace les extents vers les autres PV du VG, à chaud
sudo vgreduce vg_data /dev/sdb && sudo pvremove /dev/sdb
```

## Instantanés et thin provisioning

```bash
sudo lvcreate -s -n snap_avant_maj -L 20G /dev/vg_data/lv_donnees       # instantané classique (zone de copie de 20 Go)
sudo lvconvert --merge /dev/vg_data/snap_avant_maj                       # revenir à l'instantané
sudo lvcreate --type thin-pool -n pool -L 1T vg_data
sudo lvcreate -T vg_data/pool -V 300G -n lv_vm01                        # volume « fin », alloué à l'usage
sudo lvcreate -s -n lv_vm01_snap vg_data/lv_vm01                        # instantané thin (sans taille)
lvs -o +data_percent,metadata_percent vg_data                            # surveiller le remplissage du pool
```

> [!WARNING]
> Un pool thin plein **bloque toutes les écritures** des volumes qu'il contient. Surveillez `data_percent` et `metadata_percent`, et activez l'extension automatique (`thin_pool_autoextend_threshold` dans `lvm.conf`).

## Cache SSD et RAID LVM

```bash
sudo vgextend vg_data /dev/nvme0n1
sudo lvcreate --type cache-pool -n cache -L 100G vg_data /dev/nvme0n1
sudo lvconvert --type cache --cachepool vg_data/cache vg_data/lv_donnees
sudo lvcreate --type raid1 -m 1 -n lv_critique -L 50G vg_data            # miroir géré par LVM
```

Métadonnées sauvegardées automatiquement dans `/etc/lvm/backup` et `/etc/lvm/archive` : `vgcfgrestore` permet de revenir en arrière après une erreur.
