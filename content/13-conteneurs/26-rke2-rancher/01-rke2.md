**RKE2** est la distribution Kubernetes de SUSE pour la **production exigeante** : durcie par défaut (profil **CIS**, validation **FIPS 140-2** possible), fondée sur containerd, avec des instantanés etcd automatiques. Elle se gère très bien depuis [[02-rancher|Rancher]] mais fonctionne seule. Sa petite sœur [[05-k3s/01-presentation-installation|K3s]] vise plutôt l'edge.

## Installation

```bash
# Premier serveur
sudo mkdir -p /etc/rancher/rke2
cat <<'EOF2' | sudo tee /etc/rancher/rke2/config.yaml
token: JetonPartageRke2-2026
tls-san: [rke2.corp.exemple.fr, 10.0.20.80]
cni: cilium
profile: cis
etcd-snapshot-schedule-cron: "0 */6 * * *"
etcd-snapshot-retention: 20
EOF2
curl -sfL https://get.rke2.io | sudo sh -
sudo systemctl enable --now rke2-server
export KUBECONFIG=/etc/rancher/rke2/rke2.yaml PATH=$PATH:/var/lib/rancher/rke2/bin
kubectl get nodes
```

Le profil `cis` exige des réglages système préalables (utilisateur `etcd`, paramètres `sysctl` fournis dans `/usr/share/rke2/`). Autres serveurs : même `config.yaml` + `server: https://rke2.corp.exemple.fr:9345`. Agents : `curl -sfL https://get.rke2.io | INSTALL_RKE2_TYPE=agent sh -` puis `rke2-agent`. Nœuds **Windows** (Server 2019/2022) possibles comme agents avec Calico.

## Exploitation

```bash
sudo rke2 etcd-snapshot save --name avant-maj
sudo rke2 etcd-snapshot list
sudo rke2 server --cluster-reset --cluster-reset-restore-path=/var/lib/rancher/rke2/server/db/snapshots/avant-maj-…   # restauration
/var/lib/rancher/rke2/bin/crictl --runtime-endpoint unix:///run/k3s/containerd/containerd.sock ps
```

Mise à jour : relancer le script avec `INSTALL_RKE2_VERSION`, nœud par nœud (serveurs d'abord), ou **system-upgrade-controller** avec des `Plan`. Les charts déposés dans `/var/lib/rancher/rke2/server/manifests/` (ressources `HelmChart`) sont installés automatiquement.
