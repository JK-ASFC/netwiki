**uv** (Astral, MIT/Apache 2.0, écrit en Rust) remplace en un seul binaire **pip**, **pip-tools**, **virtualenv**, **pipx** et **pyenv**, avec une vitesse 10 à 100 fois supérieure. Pour l'administrateur, il simplifie l'installation d'outils Python (Ansible, Netmiko, NAPALM) et l'exécution de scripts avec leurs dépendances, sans toucher au Python du système.

## Installation

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh          # Linux / macOS (dans ~/.local/bin)
brew install uv                                          # macOS
```

```powershell
winget install astral-sh.uv
# ou : powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

Lire le script d'installation avant de l'exécuter, ou utiliser le gestionnaire de paquets. Mise à jour : `uv self update` (installation autonome).

## Versions de Python

```bash
uv python list
uv python install 3.12 3.13
uv python pin 3.12               # fixe la version du projet (.python-version)
```

uv télécharge des builds autonomes de Python : utile sur les distributions dont la version système est ancienne.

## Projets

```bash
uv init outils-reseau && cd outils-reseau      # pyproject.toml, .python-version, README
uv add netmiko jinja2 pyyaml                    # ajoute et verrouille (uv.lock)
uv add --dev pytest ruff
uv run python sauvegarde_configs.py             # exécute dans l'environnement du projet (.venv créé automatiquement)
uv sync --frozen                                # reproduit exactement uv.lock (CI, production)
uv lock --upgrade-package netmiko               # mise à jour ciblée
uv tree                                         # arbre des dépendances
```

```toml pyproject.toml
[project]
name = "outils-reseau"
version = "0.1.0"
requires-python = ">=3.12"
dependencies = [
  "jinja2>=3.1",
  "netmiko>=4.4",
  "pyyaml>=6.0",
]

[dependency-groups]
dev = ["pytest>=8", "ruff>=0.6"]
```

## Interface compatible pip

```bash
uv venv .venv && source .venv/bin/activate      # Windows : .venv\Scripts\activate
uv pip install -r requirements.txt
uv pip compile requirements.in -o requirements.txt --generate-hashes
uv pip sync requirements.txt
```

## Outils en ligne de commande

```bash
uv tool install ansible-core --with ansible-lint --with paramiko   # environnement isolé, commandes dans ~/.local/bin
uv tool install httpie
uv tool list && uv tool upgrade --all
uvx ruff check .                                                   # exécution ponctuelle sans installation permanente
```

C'est l'équivalent moderne de `pipx` (voir l'installation d'[[01-ansible/01-presentation-installation|Ansible]]).

## Scripts autonomes (PEP 723)

```python verifier_certificats.py
# /// script
# requires-python = ">=3.12"
# dependencies = ["cryptography>=43", "httpx>=0.27"]
# ///
import ssl, socket, datetime
from cryptography import x509

for hote in ["intranet.corp.exemple.fr", "mail.corp.exemple.fr"]:
    pem = ssl.get_server_certificate((hote, 443))
    cert = x509.load_pem_x509_certificate(pem.encode())
    reste = cert.not_valid_after_utc - datetime.datetime.now(datetime.UTC)
    print(f"{hote} : expire dans {reste.days} jours")
```

```bash
uv run verifier_certificats.py         # uv installe les dépendances déclarées dans un environnement temporaire en cache
uv add --script verifier_certificats.py rich   # ajouter une dépendance au script
```

## Entreprise, CI et production

```toml uv.toml (ou section [tool.uv] / variables UV_*)
index-url = "https://nexus.corp.exemple.fr/repository/pypi-proxy/simple"
native-tls = true            # utiliser le magasin de certificats du système (AC interne, proxy TLS)
```

- Cache partagé en CI (`UV_CACHE_DIR`), `uv sync --frozen --no-dev` en production ; images Docker officielles `ghcr.io/astral-sh/uv`.
- Derrière un proxy d'entreprise : `HTTPS_PROXY`, et `native-tls` si le proxy inspecte TLS.
- Voir [[07-python/01-environnements-gunicorn-uvicorn|applications Python en production]].
